# Интерпретатор AST учебного языка

Реализация на **C++17**. Программа получает уже построенное AST в JSON,
исполняет его и печатает значения инструкций `write` — по одному на строку.

## Сборка и запуск

Требования: компилятор с C++17, CMake 3.16+ и доступ к GitHub при первой
конфигурации. Библиотека `nlohmann/json` автоматически скачивается CMake
через `FetchContent` и не требует ручной установки.

```sh
cmake -S . -B build
cmake --build build
./build/interpreter tests/sample.json --input 5
```

Последняя команда выведет `15` — сумму чисел от 1 до 5. AST также можно
передать через стандартный ввод:

```sh
./build/interpreter --input 7 < program.json
```

Параметр `--input` содержит значения для последовательных `read` через
запятую: `--input 10,-3,42`. Если `read` требует больше чисел, выполнение
заканчивается диагностикой и кодом возврата 1. `--help` показывает краткую
справку.

## Выполнение JSON стековой машины (SM)

На странице [Abstract Machine Compiler](https://dboulytchev.github.io/sm.html)
вставьте программу в поле Program text, включите JSON format и нажмите Run.
Сохраните Representation через Download. Передайте файл интерпретатору
и укажите входные числа через запятую:

```sh
./build/interpreter --sm contents.json --input 7
```

JSON-массив распознаётся как SM и без флага `--sm`. Файл также можно
передать через stdin. `--dump-ir` покажет команды после разрешения меток
без выполнения программы.

Поддерживаются `READ`, `WRITE`, `CONST`, `LD`, `ST`, `BINOP`,
`LABEL`, `JMP`, `JZ` и `JNZ`. `READ` кладёт очередное число на
стек, `ST` снимает значение и сохраняет его в переменной, а `WRITE`
снимает значение и печатает его. Условные переходы снимают условие со
стека. В SM оба операнда `BINOP` вычисляются к моменту выполнения
команды, в том числе для `&&` и `!!`.

В режиме SM значения имеют знаковый 32-битный диапазон. Арифметические
результаты оборачиваются по модулю 2³², как в плейграунде. Константы JSON
и значения `--input` вне диапазона диагностируются. Вывод SM публикуется
после успешного выполнения программы. Ошибки выполнения указывают индекс
команды в исходном JSON-массиве (от нуля, включая метки при подсчёте).

Пример с реальным экспортом плейграунда:

```sh
./build/interpreter --sm tests/sm/control_flow.json --input 7
```

Результат — `6`, `4`, `2`, `1`, `1` по одному числу на строку.
Массивы и строки как значения программы, S-выражения, сопоставление с
образцом и связанные с ним команды областей видимости отложены.

## Формат AST

Каждая инструкция — JSON-объект с одним ключом либо строка `"skip"`. Блок
инструкций задаётся бинарным деревом `seq`; именно такой вид создаётся в
примере задания.

| Исходная конструкция | JSON |
| --- | --- |
| `skip;` | `"skip"` |
| `read(x);` | `{ "read": "x" }` |
| `write(e);` | `{ "write": e }` |
| `x = e;` | `{ "assn": { "dst": "x", "src": e } }` |
| `s1; s2;` | `{ "seq": { "left": s1, "right": s2 } }` |
| `if (c) t else f` | `{ "if": { "cond": c, "then": t, "else": f } }` |
| `while (c) b` | `{ "while": { "cond": c, "body": b } }` |
| `do b while (c)` | `{ "do": { "body": b, "cond": c } }` |

Поле `else` у `if` необязательно. Цепочка `elif` представляется как вложенный
`if` в поле `else`, как в предоставленном JSON.

Выражения имеют один из следующих видов:

```json
{ "const": 42 }
{ "var": "counter" }
{ "binop": "+", "left": { "var": "x" }, "right": { "const": 1 } }
```

Поддерживаются `+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `<=`, `>`, `>=`,
`&&` и `!!`. В соответствии с принятой для этого языка записью `!!` —
дизъюнкция («или»). Необязательная форма составного присваивания кодируется
так: `{ "assn": { "dst": "x", "op": "+", "src": e } }`, то есть `x += e`.
Для `op` разрешены `+`, `-`, `*`, `/`, `%`.

Конструкция `for (init; condition; step) body`, показанная в условии,
обычно уже разворачивается мордочкой в `seq(init, while(condition,
seq(body, step)))`; поэтому отдельного узла `for` в контракте AST нет.

## Семантика

В режиме AST значения — знаковые 64-битные целые числа (`int64_t`). Ноль является
ложью, любое ненулевое значение — истиной. Операторы сравнения и логические
операторы возвращают строго `0` либо `1`. `&&` и `!!` вычисляются лениво:
правый операнд не вычисляется, когда результат уже известен.

Деление и остаток используют правила C++ для целых чисел: частное усекается
к нулю. Деление или остаток от деления на ноль являются ошибкой. Обращение к
переменной до `read` или присваивания также является ошибкой. Составное
присваивание читает отсутствующую левую переменную как `0`; обычное
присваивание всегда создаёт/перезаписывает переменную.

## Диагностика и тестирование

Ошибки JSON, неизвестные узлы AST, неверные поля, нехватка ввода и ошибки
вычислений пишутся в `stderr` с префиксом `Error:`; успешный запуск имеет
код 0, неуспешный — 1.
Повторные ключи внутри JSON-объекта считаются ошибкой в обоих режимах.

Интеграционные тесты покрывают пример с `read` и `while`, все
арифметические, сравнительные и логические операторы (включая ленивое `!!`),
`if`, `do-while`, составное присваивание, ошибки времени выполнения,
проверку недостижимых веток и печать IR. Запуск набора:

```sh
ctest --test-dir build --output-on-failure
```

## Устройство исходного кода

- `src/cli/` читает аргументы и разбирает JSON через `nlohmann/json`.
- `src/compiler/` проверяет структуру всего AST и компилирует его в IR.
  Ошибки структуры обнаруживаются до выполнения, в том числе в ветках
  с ложным условием. Константы должны быть целыми числами диапазона int64.
- `src/ir/` задаёт типы команд и их текстовый формат.
- `src/sm/` загружает команды SM из JSON и разрешает метки в адреса IR.
- `src/vm/` выполняет IR и хранит стек, переменные и позицию во входных
  данных. Арифметическое переполнение диагностируется при выполнении.
- `tests/` содержит JSON-примеры и сценарии интеграционных тестов CTest.

IR — плоский список стековых команд. Выражение оставляет одно значение
на стеке. Команда записи, присваивание и условный переход снимают значение
со стека. Циклы компилируются в переходы на более раннюю позицию, а
`&&` и `!!` пропускают вычисление правого операнда, когда результат известен.
Адрес перехода равен индексу команды. Индекс за последней командой завершает
программу. Посмотреть IR без исполнения можно так:

```sh
./build/interpreter tests/sample.json --dump-ir
```

Для новой конструкции языка сначала определите, как выразить её имеющимися
командами, и добавьте трансляцию в компилятор AST. Если нужна новая команда,
добавьте её тип в `src/ir/ir.h`, исполнение в `src/vm/vm.cpp` и печать
в `src/ir/ir.cpp`.
