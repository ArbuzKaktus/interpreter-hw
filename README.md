# Интерпретатор AST учебного языка

Реализация на **C++17**. Программа получает уже построенное AST в JSON,
исполняет его и печатает значения инструкций `write` — по одному на строку.
Парсер исходного языка здесь намеренно не нужен: AST создаёт «мордочка»
задания.

## Сборка и запуск

Требования: компилятор с C++17, CMake 3.16+ и доступ к GitHub при первой
конфигурации. Библиотека `nlohmann/json` автоматически скачивается CMake
через `FetchContent` и не требует ручной установки.

```sh
cmake -S . -B build
cmake --build build
./build/interpreter tests/sample.json --input 5
```

Последняя команда выведет `15` — сумму чисел от 1 до 5. AST также можно
передать через стандартный ввод:

```sh
./build/interpreter --input 7 < program.json
```

Параметр `--input` содержит значения для последовательных `read` через
запятую: `--input 10,-3,42`. Если `read` требует больше чисел, выполнение
заканчивается диагностикой и кодом возврата 1. `--help` показывает краткую
справку.

## Формат AST

Каждая инструкция — JSON-объект с одним ключом либо строка `"skip"`. Блок
инструкций задаётся бинарным деревом `seq`; именно такой вид создаётся в
примере задания.

| Исходная конструкция | JSON |
| --- | --- |
| `skip;` | `"skip"` |
| `read(x);` | `{ "read": "x" }` |
| `write(e);` | `{ "write": e }` |
| `x = e;` | `{ "assn": { "dst": "x", "src": e } }` |
| `s1; s2;` | `{ "seq": { "left": s1, "right": s2 } }` |
| `if (c) t else f` | `{ "if": { "cond": c, "then": t, "else": f } }` |
| `while (c) b` | `{ "while": { "cond": c, "body": b } }` |
| `do b while (c)` | `{ "do": { "body": b, "cond": c } }` |

Поле `else` у `if` необязательно. Цепочка `elif` представляется как вложенный
`if` в поле `else`, как в предоставленном JSON.

Выражения имеют один из следующих видов:

```json
{ "const": 42 }
{ "var": "counter" }
{ "binop": "+", "left": { "var": "x" }, "right": { "const": 1 } }
```

Поддерживаются `+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `<=`, `>`, `>=`,
`&&` и `!!`. В соответствии с принятой для этого языка записью `!!` —
дизъюнкция («или»). Необязательная форма составного присваивания кодируется
так: `{ "assn": { "dst": "x", "op": "+", "src": e } }`, то есть `x += e`.
Для `op` разрешены `+`, `-`, `*`, `/`, `%`.

Конструкция `for (init; condition; step) body`, показанная в условии,
обычно уже разворачивается мордочкой в `seq(init, while(condition,
seq(body, step)))`; поэтому отдельного узла `for` в контракте AST нет.

## Семантика

Все значения — знаковые 64-битные целые числа (`int64_t`). Ноль является
ложью, любое ненулевое значение — истиной. Операторы сравнения и логические
операторы возвращают строго `0` либо `1`. `&&` и `!!` вычисляются лениво:
правый операнд не вычисляется, когда результат уже известен.

Деление и остаток используют правила C++ для целых чисел: частное усекается
к нулю. Деление или остаток от деления на ноль являются ошибкой. Обращение к
переменной до `read` или присваивания также является ошибкой. Составное
присваивание читает отсутствующую левую переменную как `0`; обычное
присваивание всегда создаёт/перезаписывает переменную.

## Диагностика и тестирование

Ошибки JSON, неизвестные узлы AST, неверные поля, нехватка ввода и ошибки
вычислений пишутся в `stderr` с префиксом `Ошибка:`; успешный запуск имеет
код 0, неуспешный — 1.

В проекте есть восемь интеграционных тестов: пример с `read` и `while`, все
арифметические, сравнительные и логические операторы (включая ленивое `!!`),
`if`, `do-while`, составное присваивание, а также четыре сценария ошибок
(неинициализированная переменная, деление на ноль, нехватка ввода, неверный
узел AST). Запуск набора:

```sh
ctest --test-dir build --output-on-failure
```

## Устройство исходного кода

`main.cpp` содержит три изолированные части:

1. `nlohmann/json` — библиотека для разбора JSON; подключается в
   `CMakeLists.txt` с помощью `FetchContent`.
2. `Interpreter::EvaluateExpression` — рекурсивное вычисление выражений.
3. `Interpreter::ExecuteStatement` — рекурсивное исполнение инструкций и изменение
   таблицы переменных.

Такое разделение позволяет расширить язык новым узлом: добавить ветку в
`EvaluateExpression` для выражения либо в `ExecuteStatement` для инструкции, после чего добавить
соответствующий JSON-файл и тест.
